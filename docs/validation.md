# Validation

Baseline: unmodified published Paseo 0.15.4 packages, Node 22.20.0, Linux x86_64. No changes were made to the Paseo repository or the normal daemon.

Release 0.1.4 preflight on 2026-11-15: all 26 unit/compatibility tests and both Chromium browser tests passed on Node 22.20.0. Type checking, linting, formatting and the package dry run also passed. The distributable contains the manifest, runtime entries and modules, overview and declared screenshot.

- `npm run test:unit`: 11 tests passed. Covers target validation, Worktree selection before targets, non-Git gating, required inputs, duplicate submission, frozen pending input and identical retry after a lost response, attachment reference retention and blocked submission during uploads/errors.
- `npm run test:compat`: 15 tests passed. Real isolated stock daemon, plugin subprocess/compiler, and SDK transport; typed test provider adapter. Exercises MCP and native tool catalogs, scoped discovery, Local/Worktree creation, parent links, concurrent completion envelopes, idempotent coordinator creation, stale targets and disabled host tools. Archive coverage includes same-workspace and cross-project workers, nested subagents, keeping workers, rejecting unrelated agents, repeated requests and retry after a partial worker failure. Optional workspace cleanup is checked both on and off with both worker choices; it archives empty task Local workspaces while preserving shared workspaces, unrelated empty workspaces, live terminals, Local files and dirty managed worktrees. Thrown and payload-level cleanup failures are reported separately from successful task archival and can be retried through the RPC. Attachment checks cover browser-style upload, host-file import, durable file integrity, coordinator image input, shared worker-path instructions, automatic attachment-tool delivery to both project workers without prompt-carried metadata, ordinary-agent exclusion, idempotent retry and invalid/missing/oversized file rejection before agent creation. A packed copy without development node_modules is also compiled and loaded by the stock host.
- `npm run test:browser`: 2 tests passed. The stock package's real web UI and Chromium, with a real isolated daemon. Desktop and compact browser layouts with 19 registered projects: bounded/searchable selection, selected-only filtering, empty-form Refresh without a features request, standard combobox selection without application dialogs, visible isolation, expandable agent options with retained settings, launch policy failure/retry, coordinator navigation and task listing. Archive tests exercise confirmation cancellation, a real daemon validation error injected through the test transport, visible retry and both worker choices. The workspace cleanup switch starts off, resets after cancellation, survives a failed archive attempt, removes empty Local workspaces and preserves kept workers' workspaces. A cleanup warning injected into the real archive response remains visible after the task card disappears and can be dismissed. File picking/removal, image upload, desktop drop, narrow-layout paste, host-file failure/retry, oversized-file errors and attachment metadata on launch are checked through the real UI and daemon. Screenshots are saved in `artifacts/`.
- `npm run typecheck` and `npm run lint`: passed.
- v0.1.0 real-provider baseline, without task attachments: `PASEO_SMOKE_MODE=full-access npm run test:real`: 1 test passed in 51.28 seconds with installed Codex 0.169.0 / gpt-6.1-sol. The user explicitly approved Full access for these throwaway test agents. A real coordinator launched two children, each returned PROJECT_CHECK after reading its README, and the coordinator's final assistant answer contained COORDINATOR_RESULT for both projects. Both Git working trees remained clean. The earlier Auto run stopped at a tool permission request without granting it.

These are separate forms of evidence. Test adapters validate the transport/lifecycle integration, not a language model's adherence to the coordinator prompt. The real-provider smoke validates model-driven delegation. Neither substitutes for native-device testing. The new attachment path has not been exercised with a real model; worker file use remains model-driven, and the tests verify the supplied context and SDK delivery.

Native iOS/Android, other operating systems and additional real providers have not been exercised. The current manifest deliberately excludes newer Paseo minor versions until their public APIs are checked.

Workspace cleanup's running setup/service guards and hidden-agent pagination have not been exercised separately. Paseo 0.15.4 has no atomic empty-workspace archive operation; creation from another client between the final occupancy check and archival remains a concurrency gap.
